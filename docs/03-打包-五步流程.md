# 03 打包：五步流程

双击 `打包桌面版.bat`，或运行 `node scripts/pack.mjs`。背后是五步。

```
[1/5] 检查构建环境      → env-check.mjs
[2/5] 检查项目文件      → node_modules / 图标 / 签名私钥 / 版本号
[3/5] 构建前端          → tsc + vite（直调，绕开 npm 包装器）
[4/5] 编译并打包        → build-desktop.mjs → cargo / tauri build
[5/5] 生成更新清单      → gen-update-json.mjs
```

## [1/5] 检查构建环境

调 `env-check.mjs`，不过就停在这里 —— **不要跳过它**。后面几步失败的报错
（找不到 windres、找不到 rustc、NSIS 下载超时）都很难读，而这一节会直接说缺什么。

## [2/5] 检查项目文件

- `node_modules` 不存在 → 自动 `npm install`
- 图标不存在 → 自动跑 `gen-icons.mjs`
- `src-tauri/.cargo/config.toml` 不存在 → 自动跑 `setup-gnu.mjs` 生成
- `.tauri-key` 不存在 → **停下并给出生成方法**（Tauri updater 强制签名）
- 从 `tauri.conf.json` 读版本号（单一来源，避免多处维护导致不一致）

其中 `.cargo/config.toml` 那一条值得说明：它记录了本机 MinGW 的**绝对路径**，
所以模板仓库里**没有**这个文件（提交了等于把别人的路径发给你）。但缺了它的后果
不是"立刻报错"，而是**白等十几分钟**：

- 编译目标会退化成 rustup 的默认 toolchain。默认若是 msvc，前面全都编得过，
  直到链接阶段才报 `could not open 'kernel32.lib'`；
- `-Wl,-exclude-all-symbols` 不生效，可能撞上符号导出上限（docs/05 第 2 节）。

所以打包流程把它当前置条件自动补齐，而不是等编译失败。想走 MSVC 路线的，
设环境变量 `WEB2EXE_NO_GNU=1` 跳过这一步。

## [3/5] 构建前端

直调 `tsc -b` 与 `vite build`，不走 `npm run build`。

原因有两个：一是省掉一层进程包装，输出更快更干净；二是绕开在不同 shell 下
行为不一致的 npm 包装器（`npm` 在 Git Bash、cmd、PowerShell 里是三种东西）。

## [4/5] 编译并打包

这一步交给 `build-desktop.mjs`，它做了五件"不做就会出玄学问题"的事：

**1. 用 Node 设置签名密码**

cmd 里 `set "VAR="` 是删除变量而非设为空串，会导致 Tauri 转交互式索要密码并卡死
（实测挂起 12 秒以上）。Node 里 `env.X = ""` 才是真正的空字符串。详见 docs/05 第 4 节。

**2. 自己补 PATH**

MinGW 解压在用户目录、不在持久 PATH 里，而 GNU 目标下 `embed-resource` 用裸命令名
`windres` 调它。目录清单由 `toolchain-path.mjs` 从 `.cargo/config.toml` 算出来，
注入子进程 —— 好处是不用重开终端。

**3. 确保 WebView2Loader.dll 就位**

见 docs/05 第 3 节。缺了它装完启动就报错，而 release 目录里看着是好的。

**4. 前端产物按时间戳判断是否复用**

只判断"文件存在"会静默把旧前端打进包（docs/05 第 7 节）。源码比产物新就重新构建。

**5. 输出实时流式打印**

首次编译 Rust 依赖要 5–15 分钟。早期用 `spawnSync` 缓冲到最后才打印，
窗口一片空白，使用者会以为卡死并强行关掉。

打包完还会做一次**内容校验**（`check-installer.mjs`）：读生成的 `installer.nsi`，
逐文件核对"声明要装的东西是不是真的都在清单里"。安装包能装 ≠ 装完能用，
这一步专门抓这个差值。

## [5/5] 生成更新清单

问你线上地址前缀（应用会从这里下载更新），然后生成 `update.json`。

没填就跳过 —— 安装包已经打好了，之后可以手动补：

```bash
node scripts/gen-update-json.mjs 0.1.0 https://你的地址/目录
```

## 产物

| 文件 | 用途 |
|---|---|
| `*-setup.exe` | 安装包，双击即可安装（当前用户级，不需要管理员） |
| `*-setup.exe.sig` | 更新签名，**必须**跟安装包一起上传 |
| `update.json` | 更新清单，放在线上目录供应用查询 |

产物位置随工具链变化（GNU 目标的路径含 triple），用这个查：

```bash
node scripts/build-status.mjs
```

它一秒钟给出：编译进度、产物路径、体积，不必等编译跑完。

## 失败时看哪里

| 报错关键词 | 原因 | 处理 |
|---|---|---|
| `export ordinal too large` | MinGW 符号导出溢出 | `.cargo/config.toml` 丢了，重跑 `npm run setup:gnu` |
| `could not open 'kernel32.lib'` | 走了 MSVC 路线但缺 SDK | 改用 GNU 路线（docs/02） |
| `找不到 windres` | PATH 没补上 | 确认 `toolchain-path.mjs` 能读出 MinGW 路径 |
| `Connection Failed` / `os error 10060` | NSIS 首次下载失败 | 配代理后重试；成功一次后会缓存 |
| 挂住不动、无输出 | 签名密码变量缺失 | 不要用 cmd 设置签名变量，走 `build-desktop.mjs` |
| 装完报找不到 DLL | WebView2Loader.dll 没进包 | 检查 `bundle.resources` 是否声明了它 |

完整日志写在 `.setup-tmp/tauri-build.log`。
